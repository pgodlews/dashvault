## Routes Detail

### `__root.tsx` — Root Layout
- Renders the top navigation for Dashboard, Clips, Viewer, Saved/Recent maps, Logs, and Settings
- Uses `<Link>` from TanStack Router for client-side navigation
- Renders `<Outlet />` for child route content
- No data fetching

### `index.tsx` — Dashboard
- Imports `useStatus()` hook for live status stream
- Renders a responsive grid of `<Tile>` components:
  - **Archive** — state badge (idle/archiving/error), last archive message
  - **Uptime** — formatted uptime string
  - **CPU Temp** — degrees °C with color threshold (green < 65, yellow < 80, red ≥ 80)
  - **Disk** tiles — one per mount (`/`, `/mutable`, `/backingfiles`), usage bar + GB
  - **WiFi** — SSID + signal bars (0–3)
- **ConnectionBadge** — dot (green live / yellow connecting / red error) + "updated Xs ago"
- Shows skeleton grid while `status === undefined`

### `clips.tsx` — Clip Browser
- **Data**: calls `ls("TeslaCam/")` on mount → parses dirs into clip events
- **State**: category filter (SavedClips / SentryClips / RecentClips), sort order
- **EventCard**: expandable; lazy-loads file list (`ls("TeslaCam/SavedClips/event-dir")`) on first expand; caches in a `Map`
- **Actions**: ZIP download (`zipUrl`), Delete (opens `DeleteModal`)
- **DeleteModal**: two-step — shows path, requires confirm, Escape/backdrop dismisses
- File detail: filename, size, formatted total per event
- CSRF: all DELETE calls use `apiFetch` (POST with X-CSRF-Token)

### `viewer.tsx` — Multi-Camera Player
- **EventSidebar**: shows `D:` entries from `ls("TeslaCam/")`, grouped by category, sorted newest-first
- **PlayerArea**: mounts when an event is selected; the key includes the exact requested clip so same-day RecentClips cannot inherit stale playback state
- **Camera detection**: `detectAngle(filename)` maps filenames containing `front`, `left_repeater`, `right_repeater`, `back`, `narrow_left`, `narrow_right` to labeled slots
- **Sync**: uses `requestAnimationFrame` loop; lead camera is `front`; others sync their `currentTime` if drift > 0.5s
- **Layouts**: Classic, Overhead, Mobile, Focus, and Board
- **GPS map**: shows the current SavedClips or RecentClips route and interpolates a marker from the front camera's source playback timestamps. **Drag the marker** along the route to move playback: it snaps to the nearest point of the track (`nearestOnTrack`, interpolated between the 1 Hz samples), playback pauses while dragging, every camera seeks at most every 150 ms (`SCRUB_SEEK_MS`) and exactly on release, then resumes if it was playing. Decoding happens in the browser; the Pi only serves file ranges. Works with both map renderers; limited to the current minute.
- **Vehicle telemetry**: heading, speed, gear, Autopilot, linear acceleration, accelerator, brake, steering, and blinkers animate with playback
- **PlaybackBar**: `<input type="range">` scrubber, speed selector [0.25, 0.5, 1, 1.5, 2, 4], mute, layout toggle
- **Actual size**: click a camera to show it at its own resolution (one CSS pixel per video pixel, e.g. 1280×960), scaled down only when the window is smaller; the label shows size and scale. Click again, click the backdrop or press Esc to return. The same `<video>` element moves into the overlay, so it stays in sync with the other cameras. Fullscreen (F) first gives it more room. The enlarged camera has its own playback bar along the bottom (back/forward 5 s, play/pause, scrubber, time; it fades after 2.5 s without mouse movement while playing) and, when the minute has telemetry, a compact vehicle panel top right (`VehicleTelemetry compact`: speed, heading, gear, Autopilot, pedal, brake, steering, blinkers). Both drive the same transport as the main player (`PlaybackControls`, registered by PlayerArea).
- **Deep links**: `?clip=<folder>/<file>` opens that folder and minute; `&t=<seconds>` starts every camera at that moment (used by Look around and trip replay). Choosing another minute starts it at 0.
- **Keyboard**: Space=play/pause, ←/→=±5s, M=mute, 1–5=layouts, Esc=leave actual size

### `map.tsx` — GPS Track History
- **Time range, Grafana style** (`lib/timeRange.ts`): the range lives in the URL, so back, reload and shared links work. `?range=24h|7d|30d|90d|all` is relative to now (default `7d`; `all` = the retention period); `?from=YYYY-MM-DDTHH:MM&to=...` is absolute, in local time (the car's clock). The header has a preset menu with a custom from/to form, **Zoom out** (twice the span, around the same middle) and Refresh.
- **Timeline strip** (`components/TimelineStrip.tsx`): driving minutes per hour (ranges up to 4 days) or per day, from `GET /api/telemetry/days`. Drag across it to select a shorter range; double-click to zoom out. Plain SVG with pointer events, so it works with touch.
- **Look around** (`components/LookAroundPanel.tsx`, `lib/street.ts`): with the header's Look around button on, clicking the map (or a track's dot) asks `/api/street/near` for the drives within about 40 screen pixels (at least 25 m) and puts the point in the URL (`?look=lat,lon&lr=m`). The panel lists the passes; for one whose video is still on the Pi it shows every camera's still at the closest moment (640 px frames from `/api/street/frame`; click one for full size), arranged as in the car. ←/→ step 1 s, Shift for 5 s; a heading arrow on the map follows. **Open video** opens the viewer at that moment (`/viewer?clip=<id>&t=<seconds>`), and **Street View ↗** opens Google Street View at the same point, looking the way the car was driving, in a new tab (Google's documented `maps/@?api=1&map_action=pano` URL; Google then knows the location). Without ffmpeg it offers a one-time install. Stepping stays within the clip's minute.
- **Trips** (`lib/trips.ts`): clips less than 5 minutes apart form a trip (Saved and Recent clips of one drive together). A panel over the map lists the range's trips newest first with time, driving time, distance and saved clips; selecting one (`?trip=<first clip start>`) shows only its clips.
- **Replay** (`components/TripReplay.tsx`): loads the trip's full tracks (`/api/telemetry/tracks?from=&to=&full=1`) and plays the driving time back (gaps between clips skipped) at 1×–60× with a slider, a heading arrow on the map (`cursor` prop of both renderers) and the viewer's vehicle panel (speed, heading, gear, Autopilot, accelerator, brake, steering, blinkers, acceleration). While a minute's video is still on the Pi, a link opens it in the viewer.
- Loads `GET /api/telemetry/tracks?from=&to=`, which returns simplified lines (`clip.line`) instead of full tracks; both renderers draw `clipLatLons(clip)`, which falls back to the full track for the viewer. Playwright: `tests/map.spec.ts`.
- One map for Saved (red) and Recent (yellow) tracks; SentryClips are never indexed. The header legend doubles as a per-category show/hide toggle (remembered per browser). Saved tracks draw above Recent where they overlap.
- Line style shows availability: solid = still on the Pi and clickable; dashed and faded = archived or overwritten.
- Colours and draw order live in `lib/telemetry.ts` (`TELEMETRY_CATEGORY_COLORS`, `telemetryTrackStyle`, `sortTracksForDrawing`) and are shared by the Leaflet and MapLibre renderers and the viewer's mini-map. Saved and Recent tracks use file-level minute IDs, so multi-minute Saved events retain independent playback and availability.
- Disabled by default; enabled and assigned a retention period in Settings.
- Extracts only front-camera SEI telemetry from new SavedClips and RecentClips after archiving, and with "Index while driving" after every snapshot.
- Stores approximately 1 Hz tracks as 15-value Float32 points on `/mutable`, one metadata file per day and one packed file per finished day; legacy four-value tracks remain supported.
- Uses only the Tesla filename for clip display/retention timestamps; MP4 PTS is used solely for playback synchronization, never filesystem timestamps.
- Available clips open the viewer; archived and overwritten clips remain labelled but non-playable. NAS playback is out of scope.

### `logs.tsx` — Live Log Tail
- **Unit tabs**: All / Backend / Archive / Nginx / Kernel (maps to Go backend unit whitelist)
- **SSE**: opens `EventSource("/api/logs/stream?unit=X")`, 500-line ring buffer
- **Level detection**: regex on line content → `error`/`warn`/`info`/`debug` class → color + left border
- **Filter**: text input highlights matches (HTML-escaped, then `<mark>` injected via `dangerouslySetInnerHTML`)
- **Follow mode**: auto-scroll to bottom; scrolling up disables follow; "Jump to latest" FAB re-enables
- **Reconnect**: on EventSource error, 5s delay then new connection

### `settings.tsx` — System and Feature Settings

The settings route includes:

- Archive backend selection, Saved/Sentry/Recent category toggles, and manual sync. With RecentClips on, camera chips choose which cameras' RecentClips are archived (`recent_cameras`; at least one stays selected). Only cameras found in the car's clip names (`detected_cameras`) are offered, or the four standard cameras before any clips exist; selecting all of them is saved as "all cameras".
- Telegram credentials, bot enablement, and test delivery; saving credentials must not implicitly disable the bot.
- Telemetry enablement, "Index while driving" (experimental), retention, raster tile URL, and optional MapLibre style URL. Retention is a preset (7, 30, 90 days, 1 year) or a custom number of days; the hint shows what is stored now (from `/api/telemetry/days`), and "Clear track history" says how much it will delete. Saving retention immediately prunes old days.
- Wi-Fi, snapshot interval, rsync keys, OTA, USB drives, BLE, and reboot controls.
- SD-card benchmark, write statistics, and endurance threshold controls.
- **Power & Thermal** (`PowerThermalSection`): interactive SVG temperature/CPU-clock history chart (CPU °C, GPU °C when available, MHz on the right axis, dashed Stage 1/2 threshold lines, hover read-out, min/avg/max badges), temperature-logging toggle (on by default), power-profile selector filtered to governors the kernel supports (`System default` by default), and dynamic thermal soft-throttling toggle (off by default) with Stage 1/Stage 2/hysteresis inputs. Types live in `lib/power.ts`.

Mutations use `apiFetch`; destructive actions retain their confirmation flows. Telemetry defaults to disabled, and RecentClips archiving defaults to disabled for fresh installs while an existing enabled value is preserved.

## lib/api.ts

```typescript
export function getCSRFToken(): string {
  const m = document.cookie.match(/(?:^|;\s*)teslausb_csrf=([^;]+)/)
  return m ? decodeURIComponent(m[1]) : ''
}

export async function apiFetch(url: string, options: RequestInit = {}): Promise<Response> {
  return fetch(url, {
    ...options,
    headers: { ...options.headers, 'X-CSRF-Token': getCSRFToken() },
  })
}
```

**Rule**: every API call that writes anything (POST) must use `apiFetch`. Read-only fetches (GET) can use plain `fetch`.

## lib/clips.ts

### `ls(query: string): Promise<LsResult>`
Calls `GET /cgi-bin/ls.sh?${query}`, parses text response:
- `d:name` — depth-1 directory
- `D:sub/name` — depth-2 directory
- `f:name:bytes` — file with size
- `s:free:total` — disk free/total bytes

### URL builders
```typescript
videoUrl(folder, filename)  → "/cgi-bin/download.sh?{folder}&{filename}"
zipUrl(folder)              → "/cgi-bin/downloadzip.sh?{folder}"
rmQuery(folder)             → "/cgi-bin/rm.sh?{folder}"   // used in apiFetch POST
```

### Camera angles
```typescript
const CAMERA_ORDER = ['front','left_repeater','right_repeater','back','narrow_left','narrow_right']
const CAMERA_LABELS = { front: 'Front', left_repeater: 'Left', ... }

detectAngle(filename: string): string | null
// Matches filename against CAMERA_ORDER entries (case-insensitive substring)
```

### Event types
```typescript
interface ClipEvent {
  label: string       // directory name, e.g. "2026-04-01_12-30-00"
  path: string        // relative to TeslaCam/, e.g. "SavedClips/2026-04-01_12-30-00"
  folderPath: string  // full ls query path
  category: 'SavedClips' | 'SentryClips' | 'RecentClips' | string
}
```

### Formatting helpers
```typescript
formatTime(seconds: number): string  // "1:02:34"
parseEventDate(label: string): Date  // "2026-04-01_12-30-00" → Date
formatEventDate(label: string): string  // human-readable
formatBytes(bytes: number): string  // "1.5 MB"
```

## hooks/useStatus.ts

```typescript
function useStatus(): { status: Status | undefined; conn: ConnectionState; lastUpdate: Date | undefined }
```

**Strategy**:
1. Opens `EventSource("/api/status/stream")`
2. On `message` event: parses JSON, updates `status`, sets `conn = "live"`, updates `lastUpdate`
3. On `error`: sets `conn = "error"`, closes EventSource, schedules reconnect after 5s
4. If `typeof EventSource === "undefined"` (SSR/old browser): falls back to `setInterval` polling `/api/status` every 10s

**ConnectionState**: `"connecting" | "live" | "error"`

## Adding a New Route

1. Create `src/routes/mypage.tsx`
2. Export a `Route` created with `createFileRoute('/mypage')()`
3. Run `pnpm dev` or `pnpm build` — Vite plugin regenerates `routeTree.gen.ts`
4. Add a `<Link to="/mypage">` in `__root.tsx` nav
5. For API calls: use `apiFetch` for POSTs, plain `fetch` for GETs
6. For status data: import `useStatus` hook — already connected to SSE stream

## Adding New Data to Status Tiles

1. Add field to `Status` interface in `src/lib/status.ts`
2. Add corresponding field to `Status` struct in `teslausb-www/go-backend/collect.go`
3. Populate it in `Collector.Collect()` in `collect.go`
4. Add `collect_test.go` test for the new field
5. Render in `src/routes/index.tsx`

The viewer groups event files by Tesla filename timestamp and opens the earliest minute for folder navigation. The Minute selector exposes every group for Saved, Recent, and Sentry events; missing cameras stay empty rather than borrowing footage from another timestamp. Map links select their exact minute, and telemetry follows the selected minute. Playback and PiP prefer a currently registered front camera, falling back to a visible camera. Layout/focus changes preserve playback time, rate, and play/pause state. Expand selects the camera and immediately switches to Focus layout.

`pnpm test:browser` runs the Playwright viewer regressions with a synthetic 30-second H.264 color fixture and intercepted API/file responses. Install Chromium once with `pnpm exec playwright install chromium`; CI installs its system dependencies too.
